# 원자에서 문명까지 (atomciv) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 초등학생이 태블릿에서 원자→분자→물질→발명→시대(철기까지)를 만들어 가는 오프라인 단일 HTML 게임.

**Architecture:** `atomciv/index.html` 한 파일에 CSS·SVG·JS 전부. 순수 로직(결합 판정, 레시피, 시대, 저장)은 `window.AtomCiv` 객체로 노출해 Node + Playwright로 테스트. UI는 같은 파일의 DOM/SVG 렌더러가 로직을 호출.

**Tech Stack:** HTML/CSS/vanilla JS (외부 라이브러리 없음), PWA(manifest + service worker), 테스트는 Node 내장 `node:test` + 사전 설치된 `playwright`.

**Spec:** `docs/superpowers/specs/2026-11-18-atomciv-design.md`

## Global Constraints

- 단일 `index.html`, 외부 스크립트·폰트·이미지 없음. 오프라인 동작.
- 터치 우선, 터치 영역 최소 56px, 화면 글은 한 줄 이내, 한국어.
- 저장: localStorage 키 `atomciv.v1`, 모든 접근 try/catch (실패해도 게임 동작).
- 원자 손 개수: H 1, O 2, N 3, C 4, Cl 1, Na 1, Si 4.
- 실패에 벌점·게임오버 없음.
- 과학 카드는 단순화 OK, 틀린 사실 금지.
- 기존 조합 게임의 이름·그림·조합표 사용 금지.

## Review Focus

1. 같은 원자 쌍을 4번 잇기 → 삼중결합에서 멈춰야 함 (`canBond` false).
2. 손은 다 찼지만 서로 떨어진 두 묶음 → 각각 따로 판정 (H₂ 두 개면 H₂ 두 번 발견, H₄ 아님).
3. localStorage가 막힌 브라우저(사생활 모드) → 오류 없이 새 게임으로 시작.
4. 레시피 재료 순서가 달라도 같은 결과 (`matchRecipe`는 순서 무관).
5. 세로 화면(768×1024)에서 서랍·실험대가 겹치지 않고 가로 스크롤 없음.

### Task 1: 분자 판정 엔진 + 테스트 하네스

**Files:** Create `atomciv/index.html` (데이터·로직 + 빈 화면), `atomciv/tests/logic.test.mjs`

**Interfaces — Produces (`window.AtomCiv`):**
- `ATOMS: {[sym]: {hands:number, name:string, color:string, trait:string}}` — 7개 원자, `trait`는 성격 한 줄 (Cl "전자 욕심쟁이", Na "전자를 잘 줘").
- `MOLECULES: {[key]: {id, name, emoji, why, ionic?:true}}` — 키는 `formulaKey` 결과. 1차 목록: H2, O2, N2, H2O, CO2, CH4, H3N(암모니아), ClH(염화수소), ClNa(소금, ionic), O2Si(모래). **CO는 제외** (C≡O 삼중결합 후 C 손 1개가 남아 손 규칙에 안 맞음 — 스펙 6.2에서 빌더 판단으로 남긴 항목).
- `formulaKey(syms: string[]) -> string` — 원소 기호 알파벳순, 개수>1이면 숫자 붙임. `['H','O','H'] -> 'H2O'`.
- 묶음 타입 `Group = {atoms:[{id:string, sym:string}], bonds:[{a:string, b:string, order:1|2|3}]}`.
- `freeHands(group) -> {[atomId]: number}`
- `canBond(group, aId, bId) -> boolean` — 서로 다른 원자, 둘 다 빈 손 ≥1, 해당 쌍 order < 3.
- `addBond(group, aId, bId) -> Group` (새 객체; 기존 쌍이면 order+1).
- `components(group) -> Group[]` — 연결 요소별 분리.
- `judge(group) -> Array<{status:'incomplete'|'known'|'unknown', key:string, molecule?:object}>` — 연결 요소마다 하나.

- [ ] **Step 1: 실패하는 테스트 작성** — `logic.test.mjs`에서 chromium으로 `file://.../atomciv/index.html` 로드 후 `page.evaluate`. 테스트:
  - `formulaKey(['H','O','H']) === 'H2O'`, `formulaKey(['Na','Cl']) === 'ClNa'`
  - H-O-H 결합 → `judge` 결과 `[{status:'known', key:'H2O'}]`
  - O=O (addBond 두 번) → known `O2`; O-O 한 번 → `incomplete`
  - C에 O 두 개 이중결합 → known `CO2`; Si 같은 방식 → known `O2Si`
  - N≡N → known; 같은 N 쌍 4번째 `canBond` → false (Review Focus 1)
  - H-H 두 묶음 → `judge` 길이 2, 둘 다 known `H2` (Review Focus 2)
  - H₂O₂(H-O-O-H) → `status:'unknown'` (규칙 맞지만 목록에 없음)
  - H에 이미 손 찬 상태에서 `canBond` → false
- [ ] **Step 2:** `node --test atomciv/tests/logic.test.mjs` → FAIL (AtomCiv undefined)
- [ ] **Step 3:** `index.html`에 위 데이터·함수 구현. `why` 문구 예: 물 "산소가 수소 둘과 손잡아. 네 몸의 70%가 물이야!", 소금 "Na가 전자를 Cl에게 줘 버려서 서로 끌어당겨!".
- [ ] **Step 4:** 테스트 PASS 확인
- [ ] **Step 5:** 커밋 `feat(atomciv): 분자 판정 엔진`

### Task 3: 물질·발명 레시피와 시대 진행

**Files:** Modify `atomciv/index.html`, `atomciv/tests/logic.test.mjs`, `atomciv/tests/e2e.test.mjs`

**Interfaces:**
- Consumes: `State.found`, `MOLECULES`.
- Produces:
  - `ITEMS: {[id]: {name, emoji, why}}` — 자연 재료: wood 나무, flint 부싯돌, clay 점토, copper_ore 구리광석, tin_ore 주석광석, iron_ore 철광석. 발명: fire 불, stone_axe 돌도끼, charcoal 숯, pottery 토기, copper 구리, tin 주석, bronze 청동, iron 철, glass 유리.
  - `RECIPES: [{inputs:string[], heat:boolean, output:string}]`:
    - wood + flint → fire · flint + flint + wood → stone_axe
    - wood + 🔥 → charcoal · clay + H2O + 🔥 → pottery
    - copper_ore + charcoal + 🔥 → copper · tin_ore + charcoal + 🔥 → tin · copper + tin + 🔥 → bronze
    - iron_ore + charcoal + 🔥 → iron · O2Si(모래) + 🔥 → glass
  - `matchRecipe(inputs:string[], heat:boolean) -> string|null` — 순서 무관(멀티셋 비교).
  - `ERAS: [{id, name, raws:string[], goal:string[]}]`: stone 석기시대 raws [wood,flint,clay] goal [fire,stone_axe,charcoal,pottery] → bronze 청동기시대 raws [copper_ore,tin_ore] goal [copper,tin,bronze] → iron 철기시대 raws [iron_ore] goal [iron,glass].
  - `eraIndex(found:string[]) -> number` — goal을 모두 가진 시대 수(최대 2), 해당 시대의 raws까지 서랍에 노출.
  - 🔥 버튼은 `fire`를 발견해야 활성.
- [ ] **Step 1: 테스트 추가** — logic: `matchRecipe(['charcoal','iron_ore'],true)==='iron'`, `matchRecipe(['iron_ore','charcoal'],false)===null`, `matchRecipe(['wood','flint'],false)==='fire'`, `matchRecipe(['flint','wood','flint'],false)==='stone_axe'`, `eraIndex([])===0`, 석기 goal 전부 → 1. e2e: 서랍 "자연" 칸의 wood, flint를 실험대에 놓고 "합치기" → 카드 "불"; 시대 0에서 iron_ore 서랍에 없음.
- [ ] **Step 2:** FAIL 확인
- [ ] **Step 3:** 구현. 서랍은 [원자] [분자] [자연] [발명] 네 칸; 분자·발명 칸은 발견한 것만. 아이템/분자 칩을 실험대에 올리고 "합치기" 버튼(+🔥 토글)으로 `matchRecipe`. 실패 시 칩이 통통 튀며 원위치(벌점 없음). 시대 상승 시 전체 화면 축하 연출 + 배경 교체. why 예: 철 "숯 속 탄소가 철광석에서 산소를 빼앗아 가서 철만 남아!", 유리 "모래를 아주 뜨겁게 녹였다 식히면 투명해져!", 청동 "구리에 주석을 섞으면 훨씬 단단해져!".
- [ ] **Step 4:** PASS 확인
- [ ] **Step 5:** 커밋 `feat(atomciv): 레시피와 시대 진행`
