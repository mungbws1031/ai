# 전자혀 요리 사전 늘리기 — 짧은 설계

- 작성일: 2026-11-25 · 대상: `cook/index.html`
- 상태: 승인 대기

## 의도
사용자: "해 보고 싶은 요리 이름을 텍스트로 치면 나오게 해줘." 지금 찾기는 앱 안 요리 약 50개뿐이라 된장찌개·김치볶음밥 같은 흔한 요리도 "없어요"가 나온다. 요리 초보가 떠올리는 집밥 요리는 거의 다 찾히고, 찾으면 바로 재료·만드는 법·요리 모드로 이어져야 한다.

사용자 추가: "요리를 처음 하려는 막막한 마음을 기똥차게 알아줘야 한다." "애들이 요리 해 줘도 안 먹어서 속상해서 위축되었다."

### 문제 정의 (IDEO식, 근거: 사용자 본인 경험 1건 — 나머지는 가설)
- **과제 질문**: 어떻게 하면 아이에게 해 준 요리를 거절당해 위축된 요리 초보가, 다시 부엌에 설 용기를 내고 아이가 먹는 한 끼를 만들 수 있을까?
- **인사이트(가설)**: 요리 초보는 "레시피가 없어서"보다 "또 실패하면(아이가 안 먹으면) 어쩌지"가 무서워 시작을 미룬다. 아이가 안 먹은 경험을 자기 실력 탓으로 받아들여 요리 자체를 피하게 된다. 그런데 아이 입맛은 실력보다 맵기·식감·낯섦·여러 번 만남에 더 좌우된다.
- **HMW**
  1. 어떻게 하면 요리를 열자마자 "이 정도면 나도 할 수 있겠다"고 느끼게 할까?
  2. 어떻게 하면 아이가 먹을 확률을 처음부터 높여 줄까(맵기 빼기·덜어 두기·모양 작게)?
  3. 어떻게 하면 아이가 안 먹었을 때 자책 대신 "다음엔 이렇게"로 이어지게 할까?
  4. 어떻게 하면 작은 성공(잘 먹은 요리)이 쌓여 자신감이 되게 할까?
- **디자인 원칙**
  - 탓하지 않는다: 안 먹은 건 실력 탓이 아니라고 먼저 말한다.
  - 시작 문턱을 숫자로 낮춘다: 시간·도구·재료 수를 맨 위에, 난이도는 익숙한 일에 빗댄다.
  - 아이 기준을 기본값으로: 매운 요리는 "아이 몫 먼저 덜기"를 단계에 넣는다.
  - 성공을 기억해 준다: 잘 먹은 요리를 모아 다음 선택을 쉽게.
  - 친구 말투, 짧게.

## 접근 방법
- **A. 앱 안 요리를 많이 늘림 (선택)** — 점검한 레시피만 내보낼 수 있고 인터넷·서버가 필요 없다.
- B. AI가 그 자리에서 레시피 생성 — 서버·비용·방침 변경, 틀린 양을 걸러낼 수 없음.
- C. 없는 요리는 인터넷 검색으로만 — 앱 밖으로 나가 숟가락 양·요리 모드를 못 씀.
사용자가 A를 골랐다. 목록에 없는 요리만 C의 "인터넷에서 찾기" 버튼으로 잇는다.

## 결정된 것
- **요리 약 100개 추가** (기존 포함 총 약 150개). 집에서 자주 해 먹는 한식 위주 + 초보가 자주 찾는 간단 양식·분식. 분류: 밥·덮밥 / 국·찌개·탕 / 볶음·조림·구이 / 반찬·무침 / 면 / 분식·간식 / 계란·두부 / 간단 양식.
- **데이터는 고정 레시피**: 요리마다 2인분 기준 재료(양념은 숟가락·컵 단위, 주재료는 g/개), 4~6단계 순서, 걸리는 시간, 다른 이름(예: 김볶밥 → 김치볶음밥, 된찌 → 된장찌개). 맛 계산 엔진은 쓰지 않는다(엔진 결과·스냅샷 불변).
- 찾기는 이름·다른 이름·재료로, 띄어쓰기 무시.
- 찾은 요리는 지금과 똑같이 **만드는 법(인분 1·2·4, 숟가락 양) → 요리 모드 → 맛보기, 장바구니 담기**로 이어진다. 인분은 2인분 기준 양에 비례해 바꾼다.
- **목록에 없으면**: "찾는 요리가 없어요" + `🌐 인터넷에서 "OOO" 레시피 찾기` 버튼(만개의레시피 검색, 앱 밖 브라우저로 열기).
- **요리마다 안심 정보**: `🍜 라면 끓일 줄 알면 OK · ⏱ 20분 · 🍳 팬 하나` 형식(난이도 비유 3단계: "계란 프라이 할 줄 알면 OK" / "라면 끓일 줄 알면 OK" / "한두 번 해 보면 OK"), 재료 개수.
- **아이 맞춤 (`kid`)**: 요리마다 아이 팁 1~2줄(예: "고춧가루 넣기 전에 아이 몫 덜어 두기", "고기는 작게 썰기"), 아이가 대체로 잘 먹는 요리엔 `👶 아이랑` 표시. 찾기 칸 아래 `👶 아이가 잘 먹는` 바로가기.
- **요리 모드 0단계 "불 켜기 전에, 이것만 준비해요"**: 재료 꺼내기·썰기 체크리스트(체크해야 다음으로).
- **다 만든 뒤**: 칭찬 + "아이 반응" 버튼(잘 먹었어요 / 조금 먹었어요 / 안 먹었어요).
  - 잘 먹었어요 → 기기에 "우리 집 성공 요리"로 저장, 찾기 칸 아래에 보여 줌.
  - 안 먹었어요 → 위로 문구 + 그 요리의 아이 팁·맛 보정("아이가 안 먹어요" 처방) + 아이들이 대체로 잘 먹는 요리 3개 추천.
- **문구(친구 말투)**
  - 찾기 칸: "뭐 해 먹을까요? 요리 이름이나 재료를 쳐 보세요"
  - 첫 화면 한 줄: "처음이어도 괜찮아요. 하나씩 같이 해요"
  - 칭찬: "끝까지 해냈어요! 오늘 한 끼, 정말 멋졌어요."
  - 안 먹었을 때: "속상하셨죠. 아이가 안 먹는 건 요리 실력 탓이 아니에요. 아이 입맛은 같은 음식을 여러 번 만나야 열려요. 다음엔 이렇게 해 볼까요?"
  - 결과 없음: "아직 이 요리는 없어요. 비슷한 요리를 골라 보거나, 인터넷에서 레시피를 찾아볼 수 있어요."
- **품질**: 지난번처럼 리뷰어가 일반 가정식 레시피와 비교해 점검(양념 양, 익힘 확인, 목록에 없는 재료 사용, 위험한 단계)하고 고친다. 테스트: 모든 요리 3단계 이상, 단계에 나오는 기름·버터·소금 등이 재료에 있음, 대표 검색어(된장찌개·김볶밥·계란말이·라면 등)가 찾힘.

## 목표 / 비목표 / 반목표
- 목표: 흔한 집밥 요리 이름을 치면 거의 다 나온다. 찾은 요리를 바로 따라 할 수 있다.
- 비목표: 모든 요리(세계 요리 전부), 사진·영상, 영양 정보.
- 반목표: 점검 안 된 레시피가 나가는 것, 짜거나 덜 익는 등 초보가 실패하는 레시피, 앱이 느려지는 것, 아이가 안 먹은 걸 사용자 탓처럼 들리게 하는 문구, 의학·영양 효과를 단정하는 문구.

## 가장 위험한 가정과 확인 방법
1. "안심 정보·준비 체크가 시작 문턱을 낮춘다" → 테스터 3~5명이 요리 하나를 고르고 시작하기까지 망설이는지 관찰.
2. "아이 팁을 따르면 아이가 더 먹는다" → 아이 반응 버튼 기록(기기 안)으로 테스터에게 물어 확인.
3. "위로 문구가 위축을 덜어 준다" → 안 먹었어요를 누른 테스터에게 "다음에 또 해 볼 마음이 들었나" 한 줄 질문.

## 빌더에게 맡기는 것
- 요리 목록 선정(위 분류에서 많이 찾는 순), 이모지, 다른 이름.
- 데이터 위치·형식(기존 RECIPES와 합칠지 새 배열로 둘지), 서비스 워커 캐시 +1, 스토어 설명 한 줄.
