# 전자혀 구글 플레이 출시 체크리스트

개발자가 아니어도 위에서부터 차례로 따라 하면 되도록 썼습니다.
각 항목을 끝내면 `[ ]` 를 `[x]` 로 바꿔 주세요.

용어 한 줄 풀이
- **AAB**: 플레이 스토어에 올리는 앱 파일입니다(예전의 APK 대신 쓰는 형식).
- **키스토어(.jks)**: "이 앱은 내가 만든 것"임을 증명하는 열쇠 파일입니다. 잃어버리면 업데이트를 못 합니다.
- **GitHub Actions(액션)**: 코드를 올리면 GitHub 가 대신 앱 파일(AAB)을 만들어 주는 기능입니다.
- **시크릿(Secret)**: GitHub 에 안전하게 저장해 두는 비밀번호·파일 칸입니다.

> **새 버전을 올릴 때마다 (처음 올릴 때 말고, 이후 모든 업데이트에 해당)**
> 1. `cook/app/android/app/build.gradle` 에서 `versionCode` 숫자를 1 올리고(1 → 2 → 3 …), `versionName` 도 알맞게 바꿉니다(예: `"1.0.0"` → `"1.0.1"`). **플레이는 이미 쓴 `versionCode` 를 거부합니다.**
> 2. 그 변경을 **main 브랜치에 올립니다(push 또는 PR 병합).**
> 3. GitHub → Actions → "Build 전자혀 Android AAB" 실행이 초록색 체크가 되면, 실행 화면 아래 Artifacts 의 `jeonjahyeo-aab` 를 받아 압축을 풀고 `app-release.aab` 를 플레이 콘솔에 새 버전으로 올립니다.
> 4. `cook/dishes.js`(요리 데이터)나 `cook/index.html` 을 고쳤다면 `cook/sw.js` 맨 위 `CACHE` 버전 숫자도 1 올립니다(예: `jeonjahyeo-v17` → `jeonjahyeo-v18`). 안 올리면 이미 쓰던 사람 폰에 옛 요리 데이터가 남습니다.
> 5. 아래 8번·10번이 이 박스를 가리킵니다.

## 0. 먼저 해 보기: 내 폰에 시험용 앱 깔기 (계정·이메일 없이 가능)

플레이 스토어에 올리기 전에 내 폰에서 앱을 직접 써 볼 수 있습니다. 홈 화면에 **"전자혀 테스트"** 라는 이름으로 깔리고, 나중에 스토어에서 받을 정식 "전자혀"와 따로 설치됩니다.

1. [ ] **파일 받기**: 휴대폰 브라우저로 GitHub 에 로그인 → 이 저장소 → **Actions** → "Build 전자혀 Android AAB" → 맨 위(가장 최근) 초록색 체크 실행을 누름 → 아래 **Artifacts** 의 `jeonjahyeo-test-apk` 를 눌러 받습니다(zip 파일).
   - 컴퓨터에서 받아 카카오톡 "나와의 채팅" 등으로 폰에 보내도 됩니다.
2. [ ] **압축 풀기**: 폰의 "내 파일"(또는 "파일") 앱에서 받은 zip 을 눌러 풀면 `app-debug.apk` 가 나옵니다.
3. [ ] **설치**: `app-debug.apk` 를 누릅니다. "출처를 알 수 없는 앱" 경고가 나오면 **설정 → 이 출처 허용**을 켜고 설치합니다. (Play 프로텍트가 "알 수 없는 앱"이라고 하면 "그래도 설치"를 누르세요. 내가 만든 시험용 앱이라 정상입니다.)
4. [ ] **써 보기 — 장 보기부터 요리까지**
   - 맛 고르기에서 맛 하나 → "🛒 살 재료 · 만드는 법" → 요리·인분 고르기 → **👩‍🍳 만드는 법 보기**
   - 장바구니에 담고, 장 보듯 "샀어요"를 눌러 보기
   - 부엌에서 장바구니 위 **👩‍🍳 만드는 법** → **▶ 요리 시작**으로 한 단계씩 따라 만들어 보기 (타이머가 울리는지, 화면이 꺼지지 않는지)
   - 다 만들면 맛보고 "밍밍해요" 등을 눌러 처방대로 고쳐 보기
   - 휴대폰 **뒤로가기 버튼**이 앱을 갑자기 끄지 않는지, 글씨가 잘리지 않는지
5. [ ] **막힌 곳 적어 두기**: "이 단계가 무슨 말인지 모르겠다", "불이 너무 셌다", "양이 많았다" 같은 걸 요리 이름과 함께 적어 두었다가 알려 주세요. 다음 버전에서 고칩니다.

- 새 버전이 나오면 같은 방법으로 받은 `app-debug.apk` 를 다시 설치하면 덮어써집니다(저장한 장바구니는 그대로).
- 시험용 앱은 스토어에 올리는 파일이 아닙니다. 스토어에는 8번의 `app-release.aab` 를 올립니다.

## 1. 플레이 콘솔 개인 계정 등록 (25달러, 신분증·기기 인증)

- [ ] **어디서**: <https://play.google.com/console> 에 구글 계정으로 로그인
- **무엇을**: "개발자 계정 만들기" → 계정 유형 **개인** 선택 → 이름·주소·연락처 입력 → 등록비 **25달러(1회, 평생)** 결제 → 신분증 사진 제출 → 안드로이드 폰에 "Play 콘솔" 앱을 깔아 기기 인증
- **끝난 표시**: 콘솔 첫 화면에 "앱 만들기" 버튼이 보임 (인증 승인에 며칠 걸릴 수 있음)
- **알아둘 점**: 개인 계정은 새 앱을 바로 공개할 수 없고, 8번의 "비공개 테스트 14일" 조건을 채워야 합니다. 그러니 이 항목은 **가장 먼저, 일찍** 시작하세요.

## 2. 서명 키 만들기·보관, GitHub 시크릿 4개 등록

- [ ] **키 만들기**: 명령어는 [`cook/app/README.md`](../app/README.md) 의 "릴리스 서명 키 만들기" 를 그대로 따라 하세요(여기에 다시 쓰지 않습니다).
  결과로 `jeonjahyeo-release.jks` 파일이 생깁니다. 이때 정한 **키스토어 비밀번호, 키 별칭(alias), 키 비밀번호**를 메모하세요.
- [ ] **보관(제일 중요)**: `.jks` 파일과 비밀번호를 **저장소 밖**(개인 클라우드 + USB 등 2곳)에 백업. 저장소에는 절대 올리지 마세요.
- [ ] **GitHub 에 시크릿 4개 등록**
  - 어디서: GitHub 저장소 → Settings → Secrets and variables → Actions → New repository secret
  - 이름과 값:

    | 이름 | 값 |
    |---|---|
    | `CJ_KEYSTORE_BASE64` | `.jks` 파일을 글자로 바꾼 값. 터미널에서 `base64 -w0 jeonjahyeo-release.jks` 를 실행해 나온 긴 글자 전체 (맥은 `base64 -i jeonjahyeo-release.jks`) |
    | `CJ_KEYSTORE_PASSWORD` | 키스토어 비밀번호 |
    | `CJ_KEY_ALIAS` | 키 별칭 (README 예시대로면 `jeonjahyeo`) |
    | `CJ_KEY_PASSWORD` | 키 비밀번호 |
- **끝난 표시**: 시크릿 4개가 목록에 보이고, `.jks` 와 비밀번호를 저장소 밖에 백업함
- **아직 AAB 를 만들지 마세요.** 올릴 앱 파일은 6번(방침 이메일 교체 + main 병합)이 끝난 **뒤에** 8번에서 만듭니다. 6번을 건너뛰고 만든 파일에는 `{{CONTACT_EMAIL}}` 가 그대로 남아 있습니다.
- **권장**: 플레이 콘솔에서 **Play 앱 서명(Play App Signing)** 에 가입하세요(첫 업로드 때 안내가 나오고, 기본값 그대로 진행하면 됩니다). 이 경우 지금 만든 키는 "업로드 키"가 되어, 나중에 잃어버려도 구글에 신청해 교체할 수 있습니다.

## 3. 앱 만들기: 이름 `전자혀`, 무료, 카테고리 "음식 및 음료"

- [ ] **어디서**: 플레이 콘솔 → 앱 만들기
- **무엇을**:
  - 앱 이름: `전자혀`
  - 기본 언어: 한국어
  - 앱/게임: **앱**
  - 무료/유료: **무료**

- [ ] 이후 "앱 콘텐츠"·"스토어 설정" 메뉴에서 카테고리 **음식 및 음료**, 연락처 이메일을 입력
- **끝난 표시**: 콘솔 대시보드에 `전자혀` 앱이 생기고, 왼쪽 메뉴에 설정 할 일 목록이 보임
- **알아둘 점**: 패키지 이름은 `com.jeonjahyeo.app` 이며 **한 번 올리면 바꿀 수 없습니다.**

## 4. 데이터 보안 양식 답변

- [ ] **어디서**: 앱 콘텐츠 → 데이터 보안
- **무엇을**: 아래 답을 선택합니다.
  - 앱이 사용자 데이터를 **수집하거나 공유하나요? → 아니요**(수집하는 데이터 없음)
  - 공유하는 데이터 → **없음**
  - 데이터는 기기 안(브라우저 저장소)에만 저장되고 서버로 보내지 않습니다. 계정·로그인이 없습니다.
  - 전송 중 암호화/삭제 요청 관련 질문은 "수집 없음"이면 나오지 않거나 해당 없음입니다.
- [ ] **광고 ID 선언**: 앱 콘텐츠 → 광고 ID → "앱이 광고 ID를 사용하나요?" **아니요** (이 앱은 광고 ID를 쓰지 않습니다).
- [ ] **기타 앱 콘텐츠 선언**: 5번에서 답하는 항목(콘텐츠 등급·타깃 연령·광고)과 위에서 답한 항목 외에 남은 선언(정부 앱, 금융 기능, 건강 앱 등)은 모두 **해당 없음** 으로 답하고 저장합니다.
- **끝난 표시**: 양식 "제출" 후 상태가 "완료"
- **Google Fonts 에 관한 주의(직접 한 번 더 확인하세요)**: 앱은 글꼴을 구글 서버에서 불러오므로, 이때 사용자의 IP 주소가 구글에 전달될 수 있습니다(개인정보처리방침에도 적어 두었습니다). 제가 이해하는 플레이 안내로는 "개발자가 수집하는 데이터"가 아닌 글꼴 서버 요청은 보통 '수집'으로 신고하지 않지만, 정책 해석은 바뀔 수 있고 최종 판단은 구글 몫입니다. 불안하면 플레이 도움말의 "데이터 보안 섹션" 설명을 읽고 한 번 더 확인하세요.
  가장 깔끔한 방법은 **글꼴을 앱 안에 직접 넣는 것(번들)** 입니다. 그러면 외부로 나가는 요청이 없어져 이 고민 자체가 사라집니다. 원하시면 개발 작업으로 요청하세요(처리 후 방침의 글꼴 문구와 버전 올림 필요).

## 5. 콘텐츠 등급 설문, 타깃 연령

- [ ] **어디서**: 앱 콘텐츠 → 콘텐츠 등급(설문), 타깃층 및 콘텐츠
- **무엇을**:
  - 등급 설문: 이메일 입력 → 카테고리 "유틸리티/참고" 계열 선택 → 폭력·성적 내용·도박 등은 모두 **아니요**. 사실대로 답하세요(쇼핑 링크는 있지만 앱 안 결제는 없음).
  - 타깃 연령: **만 13세 이상**(18세 이상도 가능)만 선택. 어린이(만 12세 이하)를 포함하면 가족 정책 심사가 붙어 까다로워지고, 이 앱에는 쇼핑 링크가 있어 권장하지 않습니다.
  - 광고: 앱에 광고가 **없다**고 답합니다(쿠팡 링크는 배너 광고가 아니라 구매 연결 링크).
- **끝난 표시**: 등급이 나오고(예: 전체 이용가) 해당 항목이 "완료"

## 6. 개인정보처리방침 URL, 연락처 이메일

방침 페이지는 **main 브랜치에 합쳐진 뒤 자동 배포가 끝나야** 인터넷에서 열립니다. 아래 순서대로 하세요. **이 6번이 끝나야 8번에서 올릴 앱 파일(AAB)을 만들 수 있습니다.** (앱 안에도 이 방침 화면이 들어가므로, 이메일을 넣기 전에 만든 파일은 쓸 수 없습니다. 서명 키가 등록돼 있으면 이메일이 `{{CONTACT_EMAIL}}` 그대로일 때 자동 빌드가 일부러 실패합니다.)

1. [ ] **이메일 확정·교체**: 사용자가 문의할 이메일을 정하고(전용 주소 권장), `cook/privacy.html` 안의 `{{CONTACT_EMAIL}}` 을 모두 실제 이메일로 바꿉니다. 파일에서 `{{` 를 검색해 하나도 안 나오면 됩니다.
2. [ ] **main 에 합치기**: 이 작업 브랜치를 PR 로 만들어 **main 에 병합(merge)** 합니다. (배포는 main 에 올라갈 때만 실행됩니다. 병합하면 AAB 자동 빌드도 함께 시작되고, 그 결과를 8번에서 받습니다. 또 GitHub 의 "Run workflow" 버튼은 이 병합 이후에야 나타납니다.)
3. [ ] **배포 성공 기다리기**: GitHub → Actions 탭에서 `deploy-pages` 실행이 초록색 체크(성공)가 될 때까지 기다립니다.
4. [ ] **브라우저로 확인**: <https://mungbws1031.github.io/ai/cook/privacy.html> 을 열어 방침 화면이 나오고 `{{` 가 없는지 확인합니다(다른 기기에서도).
   - 404(페이지 없음)가 나오면: GitHub 저장소 → Settings → Pages → Source 가 **"GitHub Actions"** 로 되어 있는지 확인하세요.
5. [ ] **콘솔에 입력**: 플레이 콘솔 → 앱 콘텐츠 → 개인정보처리방침 칸에 위 주소를 붙여넣습니다.
- **끝난 표시**: 위 주소가 열리고, 콘솔에 저장됨

```
땡기는 맛을 고르면 살 재료와 양념 양이 나오는 요리 초보용 맛 계산기
```

**자세한 설명**
```
전자혀는 장보기 전에 "오늘 뭐 땡기지?"를 살 재료 목록으로 바꿔 주는 요리 초보용 맛 계산기예요.

■ 이런 걸 할 수 있어요
• 요리 찾기: "떡볶이", "닭", "계란"처럼 요리 이름이나 재료만 쳐도 바로 만드는 법이 나와요.
• 요리 100여 개: 된장찌개, 김치볶음밥, 계란말이 같은 집밥 메뉴를 2인분 기준 재료와 단계별 순서로 알려 줘요.
• 아이 맞춤 팁·우리 집 성공 요리: 요리마다 아이랑 먹을 때의 팁이 있고, 아이가 잘 먹은 요리는 "우리 집 성공 요리"에 모아 둘 수 있어요.
```

## 8. 비공개 테스트 → 테스터 12명 → 14일 연속 → 프로덕션 신청

개인 계정은 **테스터 12명 이상이 14일 연속** 참여한 뒤에야 정식 공개(프로덕션)를 신청할 수 있습니다.

- [ ] **올릴 AAB 만들고 받기**(6번이 끝난 뒤에만): GitHub → Actions → "Build 전자혀 Android AAB". 6번의 병합으로 시작된 실행이 있으면 그것을, 없으면 "Run workflow" 를 눌러(브랜치 **main**) 새로 실행합니다. 초록색 체크가 되면 실행 요약에 **"✅ 서명된 AAB"** 가 보여야 합니다(안 보이면 2번 시크릿 이름 오타 확인, 빨간 X 에 "{{CONTACT_EMAIL}}" 문구가 있으면 6번 1단계 미완료). 같은 화면 아래 Artifacts 의 `jeonjahyeo-aab` 를 받아 압축을 풀면 `app-release.aab` 가 나옵니다.
  - 첫 업로드는 `versionCode 1` 그대로 됩니다. **이후 새 버전은 맨 위 "새 버전을 올릴 때마다" 박스**를 먼저 따르세요.
- [ ] **AAB 업로드**: 테스트 및 출시 → 비공개 테스트 → 트랙 만들기 → 새 버전 만들기 → 위에서 받은 서명된 `app-release.aab` 올리기 → 버전 이름 `1.0.0` → 저장 → 검토 후 출시
  - 위 3~7번의 필수 항목(앱 콘텐츠, 스토어 등록정보)이 비어 있으면 출시 버튼이 막힙니다. 콘솔 "대시보드의 할 일"을 모두 지우세요.
- [ ] **테스터 12명 모으기**: "테스터" 탭에서 이메일 목록(또는 구글 그룹)을 만들고, 12명 이상(여유 있게 15명 권장)의 **구글 계정 이메일**을 넣습니다.

## 9. 비공개 테스트 첫날 점검 (실기기 필수)

- [ ] 비공개 테스트 앱을 폰에 설치한 첫날, 아래 4가지를 **내 폰에서 직접** 확인하세요.
  1. [ ] 장바구니의 **구매 →** 버튼을 누르면 앱 안이 아니라 **외부 브라우저(또는 쿠팡 앱)** 로 열리고, **뒤로 가기**를 누르면 전자혀 장바구니로 돌아온다
  2. [ ] 장바구니의 **공유하기**를 누르면 카카오톡 등 공유 화면이 뜨고, 보낸 글이 "🛒 전자혀 장보기 ..." 목록 모양이다
  3. [ ] **화면 가장자리**: 앱을 열고 각 탭을 눌러 봅니다. 맨 위 상태 표시줄(시계·배터리)이나 맨 아래 제스처 바/내비게이션 바가 **위쪽 제목 부분이나 아래쪽 탭 메뉴를 가리지 않아야** 합니다. (안드로이드 15 이상에서는 앱이 화면 끝까지 그려져서 이런 겹침이 생길 수 있습니다.) 가려지면 스크린샷을 찍어 개발자에게 보내세요.
  4. [ ] **비행기 모드**를 켜고 앱을 열어도 열리고, 이전에 담은 장바구니가 그대로 보인다
     (글꼴만 기본 글꼴로 보일 수 있습니다. 그건 정상입니다.)
- **끝난 표시**: 4가지 모두 OK. 하나라도 안 되면 개발자에게 증상(어떤 폰, 어떤 화면)을 알려 주세요.

## 10. 쿠팡 파트너스 가입·승인 후 (나중에 해도 되는 일)

지금 앱의 구매 버튼은 **수수료가 없는 쿠팡 검색 링크**입니다. 제휴 링크로 바꾸는 건 승인 후에 하세요.

- [ ] **가입·승인**: 쿠팡 파트너스에 가입하고 승인 받기
- [ ] **약관 확인(꼭)**: 파트너스 약관에서 **앱 안에서 링크를 쓰는 것이 허용되는지** 확인. 허용되지 않으면 아래 작업을 하지 마세요.
- [ ] **설정 교체 — 이 단계는 개발자(또는 개발을 아는 사람)가 해야 합니다.** 구매 버튼 주소는 `cook/index.html` 의 `SHOP_CONFIG` 안 `searchUrl` 이라는 **코드(함수)** 이고, 쿠팡 파트너스 제휴 링크는 상품마다 따로 만들어지는 짧은 주소라서 주소 한 줄만 바꿔 끼우면 되는 일이 아닙니다. 개발자에게 이렇게 요청하세요: "쿠팡 파트너스 승인을 받았고 앱 안 링크 사용도 약관상 허용됩니다. `SHOP_CONFIG` 를 `affiliate: true` 로 바꾸고, 장바구니 재료별 구매 링크를 제 파트너스 계정의 제휴 링크로 만들어 주세요(링크 생성 방법은 파트너스 센터 또는 API 기준). 바꾼 뒤 '쿠팡 파트너스 활동으로 수수료를 받을 수 있음' 안내 문구가 장바구니 맨 위에 보이는지 확인해 주세요." (`affiliate: true` 가 되면 안내 문구는 자동으로 나타납니다.)
- [ ] **버전 올리기·빌드·업로드**: 맨 위 **"새 버전을 올릴 때마다"** 박스대로 합니다(`versionCode` 올리기 → main 에 올리기 → AAB 받기 → 플레이 콘솔에 **업데이트**로 올리기).
- [ ] 플레이 콘솔의 **광고 포함 여부** 답변이 달라지는지 다시 확인(제휴 링크도 광고로 볼 수 있으니 안내를 읽고 판단하세요).
- **끝난 표시**: 폰에서 구매 버튼 → 제휴 링크로 열리고, 장바구니 상단에 안내 문구가 보임
