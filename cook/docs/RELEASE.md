# 전자혀 구글 플레이 출시 체크리스트

개발자가 아니어도 위에서부터 차례로 따라 하면 되도록 썼습니다.
각 항목을 끝내면 `[ ]` 를 `[x]` 로 바꿔 주세요.

용어 한 줄 풀이
- **AAB**: 플레이 스토어에 올리는 앱 파일입니다(예전의 APK 대신 쓰는 형식).
- **키스토어(.jks)**: "이 앱은 내가 만든 것"임을 증명하는 열쇠 파일입니다. 잃어버리면 업데이트를 못 합니다.
- **GitHub Actions(액션)**: 코드를 올리면 GitHub 가 대신 앱 파일(AAB)을 만들어 주는 기능입니다.
- **시크릿(Secret)**: GitHub 에 안전하게 저장해 두는 비밀번호·파일 칸입니다.

준비물: 신분증, 본인 명의 신용/체크카드(25달러), 안드로이드 폰 1대, 구글 계정, 연락용 이메일 주소.

## 1. 플레이 콘솔 개인 계정 등록 (25달러, 신분증·기기 인증)

- [ ] **어디서**: <https://play.google.com/console> 에 구글 계정으로 로그인
- **무엇을**: "개발자 계정 만들기" → 계정 유형 **개인** 선택 → 이름·주소·연락처 입력 → 등록비 **25달러(1회, 평생)** 결제 → 신분증 사진 제출 → 안드로이드 폰에 "Play 콘솔" 앱을 깔아 기기 인증
- **끝난 표시**: 콘솔 첫 화면에 "앱 만들기" 버튼이 보임 (인증 승인에 며칠 걸릴 수 있음)
- **알아둘 점**: 개인 계정은 새 앱을 바로 공개할 수 없고, 8번의 "비공개 테스트 14일" 조건을 채워야 합니다. 그러니 이 항목은 **가장 먼저, 일찍** 시작하세요.

## 2. 서명 키 만들기·보관, GitHub 시크릿 4개 등록

- [ ] **키 만들기**: 명령어는 [`cook/app/README.md`](../app/README.md) 의 "릴리스 서명 키 만들기" 를 그대로 따라 하세요(여기에 다시 쓰지 않습니다).
  결과로 `jeonjahyeo-release.jks` 파일이 생깁니다. 이때 정한 **키스토어 비밀번호, 키 별칭(alias), 키 비밀번호**를 메모하세요.
- [ ] **보관(제일 중요)**: `.jks` 파일과 비밀번호를 **저장소 밖**(개인 클라우드 + USB 등 2곳)에 백업. 저장소에는 절대 올리지 마세요.
- [ ] **GitHub 에 시크릿 4개 등록**
  - 어디서: GitHub 저장소 → Settings → Secrets and variables → Actions → New repository secret
  - 이름과 값:

    | 이름 | 값 |
    |---|---|
    | `CJ_KEYSTORE_BASE64` | `.jks` 파일을 글자로 바꾼 값. 터미널에서 `base64 -w0 jeonjahyeo-release.jks` 를 실행해 나온 긴 글자 전체 (맥은 `base64 -i jeonjahyeo-release.jks`) |
    | `CJ_KEYSTORE_PASSWORD` | 키스토어 비밀번호 |
    | `CJ_KEY_ALIAS` | 키 별칭 (README 예시대로면 `jeonjahyeo`) |
    | `CJ_KEY_PASSWORD` | 키 비밀번호 |
- [ ] **서명된 AAB 받기**: GitHub → Actions → "Build 전자혀 Android AAB" → Run workflow. 끝나면 실행 요약에 **"✅ 서명된 AAB"** 가 보여야 합니다(안 보이면 시크릿 이름 오타 확인). 같은 화면 아래 Artifacts 의 `jeonjahyeo-aab` 를 받아 압축을 풀면 `app-release.aab` 가 나옵니다.
- **끝난 표시**: "✅ 서명된 AAB" 문구 확인 + `app-release.aab` 파일 보유
- **권장**: 플레이 콘솔에서 **Play 앱 서명(Play App Signing)** 에 가입하세요(첫 업로드 때 안내가 나오고, 기본값 그대로 진행하면 됩니다). 이 경우 지금 만든 키는 "업로드 키"가 되어, 나중에 잃어버려도 구글에 신청해 교체할 수 있습니다.

## 3. 앱 만들기: 이름 `전자혀`, 무료, 카테고리 "음식 및 음료"

- [ ] **어디서**: 플레이 콘솔 → 앱 만들기
- **무엇을**:
  - 앱 이름: `전자혀`
  - 기본 언어: 한국어
  - 앱/게임: **앱**
  - 무료/유료: **무료**
  - 선언 체크박스(개발자 프로그램 정책, 미국 수출법) 동의
- [ ] 이후 "앱 콘텐츠"·"스토어 설정" 메뉴에서 카테고리 **음식 및 음료**, 연락처 이메일을 입력
- **끝난 표시**: 콘솔 대시보드에 `전자혀` 앱이 생기고, 왼쪽 메뉴에 설정 할 일 목록이 보임
- **알아둘 점**: 패키지 이름은 `com.jeonjahyeo.app` 이며 **한 번 올리면 바꿀 수 없습니다.**

## 4. 데이터 보안 양식 답변

- [ ] **어디서**: 앱 콘텐츠 → 데이터 보안
- **무엇을**: 아래 답을 선택합니다.
  - 앱이 사용자 데이터를 **수집하거나 공유하나요? → 아니요**(수집하는 데이터 없음)
  - 공유하는 데이터 → **없음**
  - 데이터는 기기 안(브라우저 저장소)에만 저장되고 서버로 보내지 않습니다. 계정·로그인이 없습니다.
  - 전송 중 암호화/삭제 요청 관련 질문은 "수집 없음"이면 나오지 않거나 해당 없음입니다.
- **끝난 표시**: 양식 "제출" 후 상태가 "완료"
- **Google Fonts 에 관한 주의(직접 한 번 더 확인하세요)**: 앱은 글꼴을 구글 서버에서 불러오므로, 이때 사용자의 IP 주소가 구글에 전달될 수 있습니다(개인정보처리방침에도 적어 두었습니다). 제가 이해하는 플레이 안내로는 "개발자가 수집하는 데이터"가 아닌 글꼴 서버 요청은 보통 '수집'으로 신고하지 않지만, 정책 해석은 바뀔 수 있고 최종 판단은 구글 몫입니다. 불안하면 플레이 도움말의 "데이터 보안 섹션" 설명을 읽고 한 번 더 확인하세요.
  가장 깔끔한 방법은 **글꼴을 앱 안에 직접 넣는 것(번들)** 입니다. 그러면 외부로 나가는 요청이 없어져 이 고민 자체가 사라집니다. 원하시면 개발 작업으로 요청하세요(처리 후 방침의 글꼴 문구와 버전 올림 필요).

## 5. 콘텐츠 등급 설문, 타깃 연령

- [ ] **어디서**: 앱 콘텐츠 → 콘텐츠 등급(설문), 타깃층 및 콘텐츠
- **무엇을**:
  - 등급 설문: 이메일 입력 → 카테고리 "유틸리티/참고" 계열 선택 → 폭력·성적 내용·도박 등은 모두 **아니요**. 사실대로 답하세요(쇼핑 링크는 있지만 앱 안 결제는 없음).
  - 타깃 연령: **만 13세 이상**(18세 이상도 가능)만 선택. 어린이(만 12세 이하)를 포함하면 가족 정책 심사가 붙어 까다로워지고, 이 앱에는 쇼핑 링크가 있어 권장하지 않습니다.
  - 광고: 앱에 광고가 **없다**고 답합니다(쿠팡 링크는 배너 광고가 아니라 구매 연결 링크).
- **끝난 표시**: 등급이 나오고(예: 전체 이용가) 해당 항목이 "완료"

## 6. 개인정보처리방침 URL, 연락처 이메일

- [ ] **이메일 확정**: 사용자가 문의할 수 있는 이메일을 정하세요(새로 만든 전용 주소 권장).
- [ ] **교체**: `cook/privacy.html` 안의 `{{CONTACT_EMAIL}}` 을 모두 실제 이메일로 바꾸고 저장소에 올리세요(개발자에게 부탁해도 됩니다).
  - 확인: 파일에서 `{{` 를 검색해서 하나도 안 나오면 됩니다.
- [ ] **공개 주소 만들기**: GitHub 저장소 → Settings → Pages 에서 게시를 켜고, 방침 주소가 `https://<계정>.github.io/<저장소>/cook/privacy.html` 처럼 **브라우저로 열리는지** 확인
- [ ] **콘솔에 입력**: 앱 콘텐츠 → 개인정보처리방침 칸에 위 주소 붙여넣기
- **끝난 표시**: 폰이 아닌 다른 기기에서도 주소가 열리고, 화면에 `{{` 가 없음

## 8. 비공개 테스트 → 테스터 12명 → 14일 연속 → 프로덕션 신청

개인 계정은 **테스터 12명 이상이 14일 연속** 참여한 뒤에야 정식 공개(프로덕션)를 신청할 수 있습니다.

- [ ] **AAB 업로드**: 테스트 및 출시 → 비공개 테스트 → 트랙 만들기 → 새 버전 만들기 → 2번에서 받은 서명된 `app-release.aab` 올리기 → 버전 이름 `1.0.0` → 저장 → 검토 후 출시
  - 위 3~7번의 필수 항목(앱 콘텐츠, 스토어 등록정보)이 비어 있으면 출시 버튼이 막힙니다. 콘솔 "대시보드의 할 일"을 모두 지우세요.
- [ ] **테스터 12명 모으기**: "테스터" 탭에서 이메일 목록(또는 구글 그룹)을 만들고, 12명 이상(여유 있게 15명 권장)의 **구글 계정 이메일**을 넣습니다.
- [ ] **초대 링크 보내기**: 테스터에게 "웹에서 참여하기" 링크를 보내고, 각자 **수락한 뒤 스토어에서 앱을 설치**하도록 부탁하세요.
- [ ] **14일 연속 유지**: 수락 후 14일 동안 참여자가 12명 아래로 내려가지 않게 하세요(중간에 앱을 지우거나 나가면 줄어듦). 중간에 몇 명은 실제로 앱을 써 달라고 부탁하세요.
- [ ] **프로덕션 액세스 신청**: 14일이 지나면 대시보드에서 "프로덕션 액세스 신청" → 설문(테스트 방식·피드백 반영 내용) 작성 → 제출. 승인까지 보통 며칠 걸립니다.
- **끝난 표시**: "프로덕션 액세스 승인" 메일/알림 → 프로덕션 트랙에 같은 AAB로 출시

## 9. 비공개 테스트 첫날 점검 (실기기 필수)

- [ ] 비공개 테스트 앱을 폰에 설치한 첫날, 아래 3가지를 **내 폰에서 직접** 확인하세요.
  1. [ ] 장바구니의 **구매 →** 버튼을 누르면 앱 안이 아니라 **외부 브라우저(또는 쿠팡 앱)** 로 열리고, **뒤로 가기**를 누르면 전자혀 장바구니로 돌아온다
  2. [ ] 장바구니의 **공유하기**를 누르면 카카오톡 등 공유 화면이 뜨고, 보낸 글이 "🛒 전자혀 장보기 ..." 목록 모양이다
  3. [ ] **비행기 모드**를 켜고 앱을 열어도 열리고, 이전에 담은 장바구니가 그대로 보인다
     (글꼴만 기본 글꼴로 보일 수 있습니다. 그건 정상입니다.)
- **끝난 표시**: 3가지 모두 OK. 하나라도 안 되면 개발자에게 증상(어떤 폰, 어떤 화면)을 알려 주세요.

## 10. 쿠팡 파트너스 가입·승인 후 (나중에 해도 되는 일)

지금 앱의 구매 버튼은 **수수료가 없는 쿠팡 검색 링크**입니다. 제휴 링크로 바꾸는 건 승인 후에 하세요.

- [ ] **가입·승인**: 쿠팡 파트너스에 가입하고 승인 받기
- [ ] **약관 확인(꼭)**: 파트너스 약관에서 **앱 안에서 링크를 쓰는 것이 허용되는지** 확인. 허용되지 않으면 아래 작업을 하지 마세요.
- [ ] **설정 교체**: `cook/index.html` 의 `SHOP_CONFIG` 를 `affiliate: true` 로 바꾸고 제휴 링크 주소를 넣습니다. 그러면 "쿠팡 파트너스 활동으로 수수료를 받을 수 있음" 안내 문구가 장바구니에 **자동으로 나타납니다**.
- [ ] **버전 올리기**: `cook/app/android/app/build.gradle` 의 `versionCode` 를 1 → 2 처럼 올립니다(같은 번호는 업로드가 거부됩니다. 필요하면 `versionName` 도).
- [ ] **빌드·업로드**: 코드를 올리면(push) GitHub Actions 가 AAB 를 만듭니다 → 2번처럼 받아서 플레이 콘솔에 **업데이트**로 올립니다.
- [ ] 플레이 콘솔의 **광고 포함 여부** 답변이 달라지는지 다시 확인(제휴 링크도 광고로 볼 수 있으니 안내를 읽고 판단하세요).
- **끝난 표시**: 폰에서 구매 버튼 → 제휴 링크로 열리고, 장바구니 상단에 안내 문구가 보임
